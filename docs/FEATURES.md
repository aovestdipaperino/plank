# Plank-only features

plank tracks the `ds4_agent` C reference for the core agent loop, but moves faster on the user-facing side. This is the full list of things that exist only in plank; the README carries a short highlight reel and links here.

## Interface

- **Ratatui TUI** — the C reference is a plain line REPL; plank auto-selects a full-screen TUI when running on a terminal, with mouse-wheel scrollback.
- **Markdown renderer** — assistant replies render as styled markdown in the TUI via [ratatui-markdown](https://crates.io/crates/ratatui-markdown) (headings, emphasis, lists, tables), with tree-sitter syntax highlighting in fenced code blocks. The in-progress segment is re-rendered as tokens stream in, so partial emphasis and unclosed fences resolve live.
- **Animated status bar** — two rows: the working directory (home as `~`) and the git branch after a powerline glyph on the first, so the location holds still, and everything volatile on the second. The spinner verb gets a Claude-Code-style shimmer sweeping across the word while the model works, and it is drawn from the pool that matches what the agent is actually doing at that instant: reasoning verbs (`Pondering`, `Elucubrating`, `Fathoming`) while the stream is inside a `<think>` block, producing verbs (`Composing`, `Drafting`, `Wordsmithing`) while it samples the answer, workshop verbs (`Hammering`, `Chiseling`, `Prestidigitizing`) while a tool dispatch is actually running, and taking-it-in verbs (`Absorbing`, `Perusing`, `Sifting`) while the prompt is still prefilling. The index is fixed for the turn and only the pool moves, so the word tracks the phase without churning. Roughly one turn in twenty ignores all of that and claims to be `Fishing 🐟`, `Napping 😴` or `Moonwalking 🌙` instead; that roll is made once per turn, so a fun turn stays fun the whole way through. The second row shows the engine origin, the reasoning level — whose 🧠 blinks for as long as the *local* engine is prefilling or generating, so a `provider: local` sub-agent is visibly running on the local model rather than on the provider — and context as a percentage, framed by a rule above and below the prompt; the throbber/verb/token-stats progress sits on its own line just below the output, so a turn stays visibly alive even when thinking is hidden. A rotating yellow tip (`try /context to see context usage`, and ~50 others) trails the bar, cycling every couple of minutes. While a tool is running its name takes over that slot instead, blinking on an 800ms cycle and held for the whole dispatch plus 4s, so you can always see what the model is doing. While a compaction pass runs it takes over the throbber/verb line itself, replacing it with a flashing `compacting` plus an `▰▱` progress bar and percentage — driven by real prefill progress for the bulk of the bar and by the summary's length for the tail — and the line reverts as soon as the pass ends, interrupted or not.
- **Git-style diff cards** — an `edit` (or an overwriting `write`) renders a change card in the output: an `Update`/`Create(path)` header, an added/removed summary, and `@@` hunks with red-background removals and green-background additions (Myers diff via the `similar` crate). A `write` to a *new* file instead streams its content dimmed as it is generated, so you always see what lands on disk.
- **Word-wrapped prompt** — long input wraps onto the next row (word boundaries, hard-breaking overlong tokens) instead of scrolling sideways, keeping command/`!` highlighting intact across wraps.
- **Reports while busy** — `/context`, `/usage`, `/mcp`, and `/help` run mid-turn (answered from a turn-start snapshot) without interrupting the model; other commands still wait for the turn to finish.
- **Launch progress** — if the system-prompt KV cache must be rebuilt at startup, it warms behind a simple progress bar before the full UI appears; an up-to-date cache skips straight to the UI.
- **Type while it thinks** — each turn runs on a worker thread (the C reference's model-worker architecture), so the prompt stays live during generation: type the next message and press Enter to queue it. Queued messages join the conversation at the next tool round, or start the next turn when the current one settles. Esc interrupts; Ctrl-C clears the typed line first, then interrupts on an empty line.
- **Interruptible everywhere** — Esc stops generation *and* prompt prefill; the engine's cancel callback aborts mid-sync instead of making you wait out a long prompt.
- **Text selection and clipboard** — click-drag selects rendered output (WYSIWYG, wrapped lines included) and copies it to the system clipboard on release via `pbcopy` plus OSC 52 (so copy also works over SSH); Cmd-V pastes into the prompt through bracketed paste.
- **Selection in the prompt** — the same gesture works on the line you are typing: click to place the caret, drag to select, or hold Shift with the arrows, Home/End, or a word-wise Alt/Ctrl arrow. Shift+Up/Down move by logical line. The selection reverses in place *over* the existing command/`!` highlighting rather than replacing it. `Ctrl-C` copies it (and still clears the line when nothing is selected, so the old meaning survives), `Ctrl-X` cuts, `Ctrl-V` pastes, `Ctrl-Shift-A` selects everything, and typing or Backspace replaces the selection. All of it works mid-turn too, on the prompt that stays live while the model generates — the two key loops share one keymap so they cannot drift.
- **`/` command menu** — typing `/` at the start of the prompt raises a drop-up above it listing every command with its argument hint and a one-line explanation beside it, fuzzy-filtered as you keep typing and scrolled when it overflows `ui.popupRows`. Skills and prompt templates appear alongside the built-ins, tagged as such, so what a project adds is as discoverable as what ships. Up/Down pick, Tab or Enter accepts, Esc dismisses — but Enter on a line that already parses as a command *runs* it rather than completing it, so `/help` + Enter never needs a second Enter and a fuzzy highlight can never displace a command you finished typing. A test ties the menu to dispatch, so it can never advertise a command that would silently go to the model instead; the arcade easter eggs stay out of it deliberately.
- **Built-in prompt editor** — `Ctrl-G` opens a real full-screen editor on the half-typed prompt: an in-process, single-buffer fork of [Microsoft Edit](https://github.com/microsoft/edit) (MIT) rather than a shell-out to `$EDITOR`, so there is no temp file and no child process. Undo/redo, selection, clipboard, find and replace, word wrap and line numbers, all reachable from an F10 menubar. `Ctrl-S` returns the edited text to the prompt; `Esc` discards it and asks first if you changed anything. `ui.builtinEditor: false` (or a build without the `builtin_editor` feature) restores the old `$EDITOR` behaviour.
- **`@` file completion** — type `@` in the prompt to open a fuzzy typeahead over the repo's files, directories, and MCP resources, ranked with [nucleo](https://crates.io/crates/nucleo-matcher); Tab extends the common prefix, Enter drills into directories, and submodule paths are demoted so the project's own files come first. Honors `.gitignore` (tunable), quotes paths with spaces, and refreshes as files and MCP servers appear.

## Context and visibility

- **`/context`** — a visual breakdown of context-window usage by category (system prompt, tools, AGENTS.md, conversation).
- **`/usage`** — cumulative billed token usage for online models this session (input, output, and — on providers that cache prompts, like Anthropic — cache read/write with hit rate). Empty on the local engine, which has no billed usage.
- **`/compact [instructions]`** — reclaim context in escalating steps: first a *microcompact* that clears the bodies of old tool results with no model round-trip, and if that is not enough a summarization pass that rebuilds the transcript as a durable summary plus the recent verbatim tail plus the current contents of up to 5 recently read files. An optional argument steers that one summary (`/compact keep the failing test cases verbatim`), added to the standing eight-section contract rather than replacing it. Runs automatically when context gets tight, and never starts a model turn of its own; while a pass runs the window title reads `🗑️ compacting...`. Micro-compaction rewrites old tool-result bodies in place, which the engine can otherwise only handle by re-prefilling the transcript from scratch; a small KV snapshot ladder (up to 3 rungs at increasing transcript depths, see `docs/KV-CACHE.md`) lets it restore a snapshot that predates the rewrite instead, so the following turn extends forward and re-prefills only the genuine remainder. Whether an opportunistic pass is taken at all depends on both the bytes it would reclaim per token it would force back through prefill *and* on how full the context window is: the required ratio is strict while the window is roomy and relaxes to nothing as the window approaches the point full compaction would fire, since cheap relief is only worth its prefill cost when the expensive kind is the alternative. `context.microcompact` (default `true`) turns micro-compaction off entirely, at the cost of relying on full summarization alone to reclaim context under pressure.
- **Session-start context** — plank automatically injects git status, recent commits, discovered `AGENTS.md` files (a project root with only a `CLAUDE.md` gets an `AGENTS.md` link to it at interactive startup, and one with neither is offered `/init`), and the current date at the start of each session.
- **`/init`** — asks the model to analyze the codebase and generate an `AGENTS.md` for future sessions (build/test commands, architecture, gotchas). The generation turn runs quietly: tool banners, the `write` content preview and tool results are suppressed regardless of the `ui.show*` settings, so the draft never scrolls past before it lands on disk.
- **Persistent memory (`/remember`)** — layered memory files loaded into session-start context: `~/.plank/MEMORY.md` (user scope) and `./.plank/MEMORY.md` (project scope). `/remember <text>` appends a dated note to the project file, `/remember user <text>` to the user file; the file template documents the four entry types worth keeping (user, feedback, project, reference). Oversized files are tail-truncated at injection so memory can't crowd out the conversation. `/memory` opens both files as one buffer in the built-in editor, each between HTML-comment markers naming its scope and path; on save the buffer is split back along those markers and only the files whose text changed are written. Text typed between or after sections joins the section above it, and deleting a section's markers leaves that file untouched. On the plain-stdout path `/memory` prints the combined view instead.
- **Task list (`task` tool, `/tasks`)** — the model keeps a structured, model-visible task list as working memory that **survives compaction**: a `task` tool (add/update/list) maintains it, the current list is injected into every turn, and it serializes with the session so it rides `/resume` and `/checkpoint` rollback. Displayed in three tiers: a `done/total` counter in the status bar, a contextual strip of the active plus next pending tasks above the input, and the full list via `/tasks`. `/tasks` still shows whatever is stored.
- **`/repro`** — dumps a diagnostic snapshot for bug reports to `~/.plank/repro/repro-<time>.md`: the exact rendered engine input (system prompt, tools, context, full transcript) plus the runtime knobs that shape generation (model, backend, context size, sampling, think mode, engine tuning). `/repro <note>` records a description of the bug. Sub-agent sidechains are folded out of the transcript when they end, so the last 8 finished ones are written beside the main file as `repro-<time>.sub-<n>.md`, each with the sub-agent's label, task, outcome and full sidechain transcript. Read-only — the live session is untouched.
- **`/export`** — writes the current transcript to a shareable file: `/export [md|html] [path]`, defaulting to markdown and an auto-named file in the working directory (a directory path is accepted and gets the auto name). Markdown uses headings plus fenced tool output; HTML is a standalone document with inline CSS, no external assets, and every byte of model/tool content HTML-escaped. User turns, assistant prose, thinking blocks, tool calls (name plus arguments), and tool results each render as their own block. Read-only — the live session is untouched, and nothing is uploaded anywhere.
- **`/open [path]`** — edits an existing file in the built-in editor (the same Microsoft Edit fork Ctrl-G uses): `Ctrl-S` saves, `Esc` discards. Bare `/open` reopens the last file a tool call edited this session. TUI-only, and it never creates a file — a missing path is refused rather than started from empty.
- **`/insights`** — a personal usage report over every saved session, written to `~/.plank/usage-data/report.html` (owner-readable, self-contained, no network references) with a condensed summary in the terminal. Every number is deterministic: tool mix, languages, lines added/removed, files touched, commits, failure categories and per-tool failure rates, reply times, activity by hour, and sessions that were live at the same moment. The model is asked only for prose — how you work, what is working, where you lose time, what to try next — in a fixed handful of calls over the finished aggregate rather than one call per session; each section is independently droppable, so a failed call costs that section and nothing else. `/insights fast` skips the prose. Every suggestion the report makes is copyable with one click — feature snippets and prompts individually, the AGENTS.md instructions as a checklist with a copy-all — so acting on one is a paste rather than a retype. Per-session statistics are cached under `usage-data/session-meta/` and invalidated by the session file's size and mtime, so reruns are near-instant. The prose is cached the same way: `usage-data/last-report.json` holds the previous report's sections, its statistics and the mtime of every session it covered, and the sections are reused verbatim until ten sessions (or a tenth of the history) are new or have been written to — `/insights fresh` overrides that, `fast` neither reads nor writes the state. A section the previous run dropped is never reused, so it is rewritten on the next run. With a previous report on file, the new one opens with a computed "Since" strip: sessions changed, prompts, lines, files, commits, and tool or error categories that are new. Reply times, the hour chart, and overlap detection need the per-message timestamps added to the session format in 2.7.2; older sessions still contribute every other statistic, and the report says how many of them there are.

## Sessions and time travel

- **Session names (`/save`, `/rename`)** — a session gets its memorable `adjective-celebrity` name when it starts, not when it is written, and the TUI floats that name at the right end of the rule above the prompt, so the name a transcript will be saved under is visible all along. `/save` writes it without quitting (transcript plus KV payload); `/rename <name>` retargets later saves. A rename never touches what is already on disk: the old file stays resumable under its old name, so the next save is a logical copy rather than a move. Names are validated, not sanitized (letters, digits, `-`, `_`, `.`), and a name already on disk asks before taking it — the confirmation is the `ask` panel in the TUI and a `[y/N]` prompt on the plain path, declining by default wherever there is nobody to ask.
- **`/resume` and `/tag`** — in the TUI a bare `/resume` opens an interactive picker over every saved session: a search box that filters on name, title, tag and last prompt as you type, rows showing the session's title with its age and size, Space to preview the last turns, `Ctrl+R` to rename, `Ctrl+X` twice to delete one, `Ctrl+W` twice to delete them all (the confirmation names the count, and the wipe takes transcripts and KV payloads but leaves the shared system-prompt and project checkpoints alone), Enter to resume. On the plain-stdout path (and with `--non-interactive`) it stays the numbered listing it always was, each row led by its name, then its title, tag, age and last prompt. `/resume <name>` (or a number from the list) continues one directly, from either front end. Titles come from the transcript's first genuine user turn — the session-start context plank injects is skipped, or every session in a project would be titled after its `CLAUDE.md`; `/retitle` re-derives the titles of sessions saved before that rule, rewriting only the title record so the ages the picker sorts on survive. Replay leaves out the session-start context plank injected itself — agent instructions, persistent memory, the sub-agent roster, git status, the date — since that is context for the model, not conversation to show back. `/tag <text>` labels the current session for the listings. Listing metadata is stored in a trailer record read with bounded head/tail reads, so `/list` and `/resume` never parse whole transcripts.
- **Session KV payloads and `/strip`** — the engine's KV state is snapshotted to a fingerprinted sidecar (`<sha>.kv_raw`) next to the transcript — on `/save`, and now also at the end of every turn that changed the transcript and on interrupt — so `/switch` and `/resume` restore it and skip re-prefilling the whole conversation, and a crash or `Ctrl-C` mid-session still leaves a usable KV behind. The fingerprint ties the payload to the exact model, system prompt, and transcript; anything stale is ignored and rebuilt by a normal prefill. `/strip <sha>` drops a session's payload to reclaim disk (the transcript survives), reporting the token count a later resume will re-prefill; `/list` shows each session's payload size or `stripped`.
- **`/checkpoint` and `/rollback`** — `/checkpoint <name>` snapshots the current conversation (transcript plus live engine KV) under a name; `/rollback <name>` truncates back to it and restores the KV, so a rollback resumes with no re-prefill. A rollback first auto-saves the current tail as `pre-rollback`, so it is itself undoable. `/checkpoint` with no argument lists the checkpoints. On an engine without KV snapshots (the echo stub) it degrades to transcript-only rollback.
- **Session branching (`/tree`, `/fork`, `/clone`)** — a session is a tree of messages, not a line. `/tree` draws it, collapsing linear runs and marking the active branch, and numbers the fork points (the real user prompts on the active branch). `/fork <n>` rewinds the live transcript to just before that prompt and keeps everything after it as a sibling branch, so a different approach can be tried without losing the old one; `/clone` duplicates the active branch so the original is frozen while the copy continues. Both are shaped around the KV discipline: a fork leaves the transcript a strict prefix of what it was and a clone leaves it identical, so the engine's token common-prefix probe reuses the cached prefix instead of re-prefilling, and no KV bytes are ever reinterpreted across branches. Branches persist with the session (extra `node` records after the transcript); a linear session writes none, and pre-branching session files load as a single-branch tree.
- **`/kvcache`** — the KV cache as the tree it actually is. Every persisted snapshot carries a JSON metadata sidecar recording what it is, the fingerprint of the snapshot it extends, the model and reasoning level behind it, its size, its hit count, when it was last used, and whether it is pinned — so the tier chain that was previously implicit in a chain of hashes is now inspectable. `/kvcache` draws it with `↑↓` to move, `←→` to fold, `p` to pin, `d` to delete, `g` to sweep; the plain REPL prints the same tree and takes `pin|unpin|rm|gc` by fingerprint prefix. Metadata is strictly advisory: the signature inside a snapshot's own body remains the only thing that decides whether its bytes may be restored, so a corrupt or missing sidecar costs display quality and never correctness.
- **Age-and-budget cache retention** — snapshots expire on time since last use (`kvcache.ttlSessionDays`, default 14; `kvcache.ttlTierDays`, default 30), and if the survivors still exceed `kvcache.maxBytes` (default 20 GB) the least-recently-used are evicted until they fit. Pinned entries, the chain the current launch is using, and any snapshot something newer still builds on are all exempt, and a budget is a target rather than a licence: when everything remaining is protected plank stays over budget instead of deleting something it should not. This replaced a policy that kept only the *current* system-prompt and project fingerprints and deleted every sibling, which meant switching model or reasoning level and back paid a full system-prompt re-prefill each way. Multiple system prompts now coexist for as long as they are in use.
- **`/clear`** — resets the session in place.

## Delegation and side questions

- **`/subagent`** — `/subagent <task>` delegates a task to a sidechain run of the same model: the subagent works with full tool access on a fork of the conversation, and only its final report is carried back into the transcript (framed as background context). The fork shares the conversation's KV-cache prefix going in and is rolled back afterwards, so delegation costs one report instead of the whole sidechain.
- **Named agents (`/agent`, `/subagent:<name>`)** — agent definitions in `~/.plank/agents/*.md` (overlaid by `./.plank/agents`, frontmatter `name`/`description`, body = instructions) become dispatchable roles: `/agent` lists them and `/subagent:<name> <task>` runs the sidechain with that definition's instructions. The name rides on the command token rather than the argument, so a task whose first word happens to match a definition is never silently reinterpreted as a persona, and a name that does not exist is reported instead of quietly falling back. The TUI colours the `:<name>` green when it resolves and red when it does not, so a typo shows before Enter. (Parallel team orchestration is still tracked, pending per-session KV save/restore.)
- **`agent` tool (model-invoked delegation)** — The same sidechain machinery as `/subagent`, but callable by the **model**: it delegates a bounded `task` to a fresh scoped sub-agent (optional `name` selects a persona) and gets back only the final report, keeping the main transcript free of the intermediate research. Nesting is depth-capped so a sub-agent cannot itself delegate.
- **`/goal`** — `/goal [--max <n>] <objective>` hands control back to the model turn after turn until the objective is settled, instead of you typing "continue". After each turn plank asks for a one-line adjudication (`ATTAINED`, `UNATTAINABLE`, `NEEDS_USER` or `CONTINUE`) and stops on the first terminal verdict, printing a closing line with the reason and the iteration count. Anything unparseable — or a reply that does work rather than answering — reads as `CONTINUE`, so a parse miss costs an iteration instead of falsely declaring success, and the cap (20 by default, `--max` to change it) bounds the loop. Ctrl-C in the plain REPL and Esc in the TUI end the goal, not just the turn in flight, and lines you type mid-goal still run as ordinary follow-up turns.
- **Cross-engine sub-agents** — a definition's frontmatter can name the engine its sidechain runs on, independently of the main agent: `provider:` (`openai`/`anthropic`) plus `model:`, with optional `base-url:`, `ctx:` and `api-key-env:`. Only the *name* of the key variable is configurable, never the key, so a definition file stays committable. `provider: local` names the local ds4 engine specifically — under a remote main agent plank loads the local model alongside the provider so such a sidechain has something to run on, which costs the full ~82 GB residency and therefore happens only when a definition actually asks for it. Omitting `provider:` still means "whatever the parent is", which under `--provider` is the remote model; the two intentions are no longer spelled the same way. `/agent` shows each definition's engine, and the key variable to set when it is missing. The roster the *model* sees rides in the session context rather than the system prompt, so editing a definition rebuilds the small project-tier KV cache instead of invalidating the fingerprinted 1M-token prefix. Provider-backed definitions with `max_parallel > 1` fan out concurrently, capped by `agents.maxParallel`; a sidechain is clean-room either way, so only the framed task crosses the wire, never the parent transcript.
- **Agent roster** — a sub-agent's output no longer vanishes, and you can see what every agent is doing at a glance. Once anything has been delegated, a roster appears below the status bar: `main` first, then one row per run with a state bullet (`●` working, `○` finished), the agent's name, the task it was given (flattened to one line and elided to fit — never a tail of its streamed output, which lands mid-statement on whatever the model is writing), and — flush right — how long it has been going and, once counted, what it has spent in tokens. Both the model-invoked `agent` tool and `/subagent` feed it, and a concurrent fan-out shows every agent as its own row, each with its own output buffer, so their streams stay separable. **`←`** on an empty prompt reaches into the roster (the signpost line says so), `←`/`→` walk the rows, **Enter** expands the selected agent's output over the transcript with its own scroll position, and **Esc** comes back. The roster is a live readout, so it appears when the first agent starts and disappears once the last one finishes — it never leaves stale rows pinned under the status bar. It does stay put while you are reading it (cursor showing, or a pane expanded), and `←` brings a finished roster back so a report you delegated is still reachable. The main log gets only a one-line signpost, so delegation keeps the transcript clean. The roster keeps the last eight runs, never evicting one that is still going, and gives its rows back to the scrollback on a short terminal. The plain REPL prints sub-agent output inline instead (there is no roster to select from), and `--non-interactive` stays silent so its stdout protocol is not corrupted.
- **`/btw`** — ask a side question *while the agent is working* without disturbing the task. `/btw <question>` is answered from the shared conversation context with tools disabled and nothing written to the transcript (it never enters history, compaction, or the next turn). By default a mid-generation `/btw` genuinely **suspends** the running reply: the generation freezes, the aside is answered, and the task resumes byte-for-byte where it left off with zero re-prefill (`--disable-btw-suspend` falls back to the older pause-and-rerun boundary queue). While the answer streams the screen splits — main conversation 60% on the left, the side answer 40% on the right — and Esc cancels it and restores the full-width view. The side prompt reuses the live KV prefix, so it costs only the framed question.

## Tools and extensibility

- **`glob` tool** — the model can find files by name pattern across the tree (`**/*_test.rs`, `src/**/mod.rs`) instead of shelling out to `find`. `**` crosses directories, `*` stays within a path segment, results are relative and capped, VCS metadata is skipped.
- **Git worktrees (`EnterWorktree` / `ExitWorktree`)** — An isolated second checkout of the repository at `<repoRoot>/.plank/worktrees/<name>` on branch `worktree-<name>`, so a large or speculative change never lands in the tree you have open. Entering switches every tool's working directory; leaving takes `keep` (the worktree and branch stay for review or merge) or `remove`. Removal is fail-closed: one holding uncommitted files or commits that exist on no other ref is refused unless `discard_changes` is passed, and so is one whose state git could not be asked about — not knowing is not the same as knowing there is nothing there. `--worktree NAME` / `--worktree-pr N` start a whole session in one, making it the session's project (its hooks, sub-agent definitions, and settings are the ones found there). `isolation: worktree` on a sub-agent definition — or `worktree.isolateAgents` for all of them — gives each run its own throwaway worktree so a fan-out cannot overwrite itself; a clean one is removed afterwards, one holding work is kept and its path reported back. Abandoned throwaway worktrees from a killed process are swept at startup, and only ever ones whose names have the exact shape plank generates. `WorktreeCreate` / `WorktreeRemove` hooks replace the git backend entirely, for a non-git VCS. Tuned by `worktree.sparsePaths`, `worktree.symlinkDirectories`, and a `.worktreeinclude` file listing gitignored files to carry into each new worktree.
- **Plan mode (`EnterPlanMode` / `ExitPlanMode`)** — A read-only propose-then-approve gate the model can enter itself: while active, `write`/`edit`/`bash` are refused and read-only tools (read/list/glob/search, web, MCP) stay available, so the model surveys the code before touching it. `ExitPlanMode` presents the proposed plan through the `ask` panel for approval (Approve lifts the gate, Keep-planning holds it); non-interactive runs auto-approve so scripts don't wedge.
- **`/skills` and the `skill` tool** — markdown prompt templates in `~/.plank/skills/<name>/SKILL.md` (overlaid by `./.plank/skills`) become slash commands: frontmatter gives `name`/`description`/`argument-hint`, the body is injected as the user turn with `$ARGUMENTS` substituted. The **model** can also invoke a skill itself via the `skill` tool (call with no name to enumerate), so a packaged procedure fires when the agent recognizes the task, not only when the user types the command; recursion is depth-capped.
- **`/templates` prompt templates** — a lighter-weight sibling of skills (issue #67): a single markdown file at `~/.plank/templates/<name>.md` (overlaid by `./.plank/templates`, project wins) becomes `/<name>`. The stem is the command name, optional frontmatter gives `description`/`argument-hint`, and the body interpolates `{{var}}` holes filled from `key=value` and positional arguments (`{{{{`/`}}}}` escape literal braces). A missing or unknown variable is a hard error naming it, never a silent empty substitution, and a template can never shadow a built-in command.
- **Hierarchical MCP configs with `primaryTools`** — user-scope plus project-scope config files, and per-server control over which tool schemas go in the system prompt. `/mcp` inspects the state of connected servers.
- **MCP resources** — beyond tools, plank speaks the MCP *resource* protocol: `mcp_list_resources` and `mcp_read_resource` let the model reach content a server publishes as addressable resources (text inlines, binary reports type and size), and the same resources appear in `@` completion. Advertised only when a connected server actually publishes resources.
- **`/install-claude-plugin <url|owner/repo> [plugin-name] [--force]`** — plank already understood the Claude Code plugin layout (`.claude-plugin/plugin.json`, `commands/`, `hooks/hooks.json`, `.mcp.json`, `settings.json`); this is the missing way to acquire one. Takes a GitHub repo URL, an `owner/repo` shorthand, a browser-copied `/tree/<ref>/<path>` or `/blob/<ref>/<path>` URL (clones the repo and resolves the plugin at that path, walking up to the parent when the path names the `.claude-plugin` directory itself), a marketplace repository (one with `.claude-plugin/marketplace.json`, which needs a plugin name and lists the names on offer when it's missing or wrong), a `.tar.gz` over https (http only to loopback, including the common case of everything nested under one top-level directory), or a local directory (cloned if it's a git repo, copied otherwise, so a plugin can be tried before it's published). Installs land in `~/.plank/plugins/claude/<name>/`, a third scan root after `~/.plank/plugins/dev/*` and before `<cwd>/.plank/plugins/*`, so a self-authored plugin still wins a bare-name collision and a plugin's contribution is always addressable as `<plugin>:<name>`; `/plugins` lists it with origin `claude` and `/plugins remove <name>` removes it. Refused: no `.claude-plugin/plugin.json`; a symlink whose target escapes the plugin tree; an unusable plugin name; an already-installed name; and a hook event plank doesn't implement — Claude Code defines `Notification` and `SubagentStop`, which plank has no equivalent for, and only this last refusal is waivable with `--force`, installing those hooks but leaving them permanently inert. Two things are rewritten at install time because the formats genuinely differ: `${CLAUDE_PLUGIN_ROOT}` (which Claude Code's hook commands reference, but plank's hook runner execs `/bin/sh` with no injected environment, so it would silently expand to empty) is rewritten to the install path in `hooks/hooks.json` and `.mcp.json` — moving the directory afterwards breaks those hooks, and the command says so when it happens — and Claude Code's top-level `"hooks"` wrapper around its events is unwrapped, since plank reads events at the top level. `.mcp.json` and `settings.json` need no translation: plank's existing plugin loaders already merge them, and a plugin's settings already sit below the user's own. Verified end to end against `obra/superpowers` v6.3.0, installed from a `/tree/main/.claude-plugin` URL via its marketplace, with plank loading all 14 of its skills on the next start.
- **Expanded hooks** — command hooks from `~/.plank/hooks.json` + `./.plank/hooks.json` (reference-compatible shape). Beyond `PreToolUse`/`PostToolUse`/`Stop`, hooks fire on `UserPromptSubmit`, `SessionStart`, `SessionEnd`, `PreCompact`/`PostCompact`, and `PostToolUseFailure`; several can inject context into the turn. An optional JSON response envelope adds `continue:false`, non-blocking `systemMessage`, `suppressOutput`, and `async` execution over the exit-code protocol; matchers can key on arguments (`bash(git *)`, `write(*.md)`); and a `prompt` hook type feeds text to the model instead of running a process. `/hooks` lists what is configured.

- **`ask` tool** — when a turn is genuinely ambiguous, the model can pose a multiple-choice question (2–4 options, single or multi-select) instead of guessing or emitting a wall of prose. In the TUI it renders a selectable panel above the input (arrow keys move, Space toggles for multi, Enter accepts); the plain REPL prints a numbered list and takes a number or label prefix. Escape declines and the turn continues; in `--non-interactive` mode there is no user, so the tool returns immediately telling the model to proceed on its own rather than blocking.

## Shell and configuration

- **`!` and `!!` commands** — both run a shell command immediately from the prompt (no model round-trip); output streams into the UI as it is produced, with exit-code display, and Esc/Ctrl-C kills it. `!!` keeps the result to yourself; `!` also records the command and its output in the transcript as a single caveated user message, so the model has it as history on your next prompt without a turn being spent on it.
- **Mode-aware, directory-aware history** — arrow-key history on a `!` line cycles past shell commands only, and history is tagged with the directory it was entered in, so one project's commands stay out of another's (legacy untagged history stays universally visible).
- **Bash sandbox** — Seatbelt sandboxing for model-initiated shell commands, on by default on macOS and disabled with `--no-sandbox` or `"enabled": false` in `~/.plank/sandbox.json` / `./.plank/sandbox.json`: commands run under `sandbox-exec` with writes limited to the working directory and temp dirs, plus configured `writablePaths`; `excludedCommands` glob patterns skip the sandbox (convenience, not a security boundary). Sandbox denials get a `[sandbox blocked: ...]` hint in the tool result so the model can react. `~/.plank` is read-only too: a model command that names it and could write (anything but a pipeline of known readers such as `cat`, `ls`, `grep` with no redirect) asks once whether to allow the write for that command or the session. User-typed `!` commands are never sandboxed — typing the command is the authorization.
- **`settings.json`** — persistent preferences for engine defaults, `@`-completion UI, safety defaults, the MCP timeout, display toggles (`showToolCalls`, `showToolResults`, `showThinking`), layered user-scope then project-scope. A startup line names any setting in force, so a file that quietly selects the CPU backend can't hide. Changes apply live, except the handful whose subject is built once at startup: the `engine` group, `safety.sandbox`/`btwSuspend`, and the prompt-shaping `tools.recall`/`fanout`/`runCode` and `git.signCommits`, since the system prompt is KV-cached per session.
- **Debug console mirror** — `ui.showThinking` is off by default, and while it is off plank mirrors its whole raw model stream to [turbo-debug-console](https://github.com/aovestdipaperino/turbo-debug-console) if one is listening on port 7878, so hidden reasoning is visible in a window of its own instead of lost. Each session gets a window named `plank:<session-name>` that survives plank exiting, so a restart appends below a `-- reconnected --` rule rather than starting over. Quitting plank writes a closing `_plank disconnected: session ended_` rule into every window it holds, the parent's and any sub-agent's, so a window left on screen says why its stream stopped instead of just going quiet; a force quit says so explicitly, since that is the exit where the turn is lost. Entirely optional: with no console running plank connects to nothing and says nothing, and a console closed mid-turn just drops the mirror. Sub-agents get windows of their own — `plank:<session>:subagent-<n>`, numbered in spawn order — so a fan-out’s concurrent slots are readable side by side instead of interleaved into one stream; each window retires when its sub-agent finishes. The console renders with `trace-stream`, the same crate plank uses for its own output, so the two cannot drift.
- **`/config`** — edit those preferences without leaving the session: an interactive TUI modal (arrow-key through fields, Enter/Space to toggle or edit, Esc to save) or a one-shot `/config <section>.<key> <value>` from the prompt. Changes write `./.plank/settings.json` (preserving unknown keys) and apply live to the running session.
- **`--ui-remote`** — a loopback control port for debugging convoluted TUI scenarios: `snapshot` captures the screen as ANSI text, `keypress` injects keys, and `uitree` returns the rendered layout as JSON, with replies ordered after the injected keys take effect so a harness never has to sleep.
- **`/remote-control` (`/rc`)** — toggles the remote-control server from inside a running TUI session, no flags needed: bare `/rc` flips it, `/rc on`/`/rc off` are explicit and case-insensitive. Turning it on binds an ephemeral loopback port and mints a fresh token, printing `http://127.0.0.1:PORT/?t=TOKEN` plus an `ssh -L` tunnel hint; opening that link auto-connects the bundled web client and claims control immediately, since typing the command is the operator's consent. `/rc off` tells connected clients, shuts the listener down, and invalidates the token, so a stale link is refused; the next `/rc` mints a new port and token. TUI-only — there is no headless or piped-REPL remote drive, and `/rc` in those front-ends declines rather than starting a server nothing can drive.
- **The bundled web client** — a single self-contained page, served by plank itself with no external request of any kind. It mirrors the session in plank's own dark theme: assistant replies render as markdown (headings, lists, fenced code, links, blockquotes) re-rendered on every streamed chunk, so structure forms as it arrives, and the model's own line breaks are kept rather than folded the way strict markdown would. The header shows the same "where am I?" segments as the TUI footer — directory, git branch, engine origin, reasoning level — plus the control role and a live context gauge. The prompt is a three-row box: Enter sends, Shift+Enter opens a line, ↑/↓ walk the prompts already sent. `send` is enabled only with something to send and `stop` only while a turn is running, so the pair says what the session can actually do. Everything typed goes as one frame kind and the agent's own slash dispatcher routes it, so `/btw`, `/clear` and the rest work from the browser exactly as from the keyboard — and a `/clear` clears the page too, rather than leaving a session that no longer exists on screen. A dropped socket says so in bold red with its close code and disables the prompt, since nothing typed after it reaches the agent and there is no reconnect to wait for — the token died with the server.
- **End-of-turn notification, remotely** — the local desktop notification only reaches whoever is at the machine plank runs on, which is exactly the person a remote session is not. A finished turn now also crosses the wire: the page raises a browser notification when permission allows, an in-page banner that needs no permission at all, a short blip, and a tab-title flash while the tab is hidden. The `plank remote <ws-url>` terminal client prints the line with a BEL. It follows the same `ui.notifyAfterSecs` threshold as the local one (10s by default), so a quick turn stays quiet everywhere.
- **`plank remote <ws-url>`** — the terminal client for the same server: authenticates with the token, mirrors output, sends typed lines as prompts (slash lines as commands, `/btw <q>` as a side question) and Ctrl-C as an interrupt. `--resume-from <id>` replays only what is newer than a bus event id, so a dropped connection picks up where it left off inside the reconnect grace window.

## The arcade

- **Screensaver** — after `ui.screensaver` of an idle prompt (`1m` by default, or `2m`, `5m`, `never`) the screen is taken by an ambient screen, and the next key or mouse event puts the UI back — the waking event is consumed rather than typed into the prompt. `ui.screensaverFace` picks which: `matrix` (the falling glyphs, the default), `starfield` (the perspective starfield), `minions` (two minions on the shore of a night lake), or `random` for a fresh draw each time, which is what it always did before the setting existed. It is not an easter egg and not a command: it is unaffected by `ui.easterEggs`, and it never appears mid-turn or over the `/config` form, since the outer input loop is the only place that can be idle.
- **`/matrix`** — the rain on demand, an easter egg like the games but with nothing to play: columns of half-width katakana falling on a black screen, a near-white glyph at the head of each and a trail fading behind it. `↑`/`↓` and the wheel set the fall speed, `c` cycles the alphabet (katakana, binary, ASCII) for fonts that cannot draw kana, and `t` puts it over live model output like any other easter egg. It keeps no state, so it is never parked and every `/matrix` is a fresh downpour.
- **`/minions`** — the pair on demand, an easter egg like the games but with nothing to play: they walk the shore, blink, elbow each other and fall about laughing, reflected in the water below them. Six poses of ASCII paint-by-numbers (`src/resources/minions.txt`) packed at build time into 218 bytes of the binary; everything else — the walk, the bob, the nudge, the laughter, the stars, the reflection — is generated. `↑`/`↓` and the wheel set the pace, `r` strips the night back to the two of them, and `t` puts them over live model output, where the `█▓▒░` coverage ramp doubles as the alpha channel and anything too faint to see is not drawn at all rather than punched through the text. It keeps no state, so it is never parked and every `/minions` is a fresh walk.
- **Five games, playable during a turn** — `/pelota`, `/breakout`, `/invaders`, `/centipede`, `/frogger`. They are the only commands besides the read-only reports that run mid-turn, because waiting on a generation is the whole point of them: opened while the model streams, they render as a translucent layer over the live output. Each keeps its own game, so closing one and reopening it resumes where it was (`new` deals a fresh one); `sound` adds terminal-bell blips, off by default. Keyboard and mouse both steer, and the first `Ctrl-C` closes the game rather than interrupting the model. Deliberately absent from `/help` and the completion popup, and behind `ui.easterEggs` (on by default) — off, they stop being known commands rather than merely hidden, so the line goes to the model like any other unrecognized one. See the [README](../README.md#the-arcade) for controls and for what "translucent" and "sound" do and do not mean in a terminal.
- **Breakout during the model download** — the one place a game runs outside a turn. An 87 GB transfer takes hours, so a round sits above the progress gauge; it is decoration and never delays the download, Esc puts it away, and `q` or Ctrl-C abort from anywhere so a rally can't trap the user. Not gated on `ui.easterEggs`: there is no prompt to type a command at yet. See [Model download](../README.md#model-download).
